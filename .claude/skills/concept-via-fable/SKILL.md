# 用寓言讲概念

## 这个 skill 干什么

有人给一个概念（必须是研究生水平的、不是常识），用一段 600-900 字的现代隐喻故事把它讲明白。**故事的揭晓段才把概念名说出来**，故事之后给"概念解释 + 隐喻对照表 + 边界说明"三件套。

不做什么：不给常识科普、不讲笑话、不写童话、不讲历史故事。**唯一目的：让一个读过研究生的知识工作者看完后，对这个概念有"先感受、后定义"的双重理解。**

## 输入槽位

| 槽位 | 是否必填 | 缺失时的动作 |
|---|---|---|
| **concept** | ✅ 必填 | 直接问"你想听哪个概念？"，不猜 |
| **domain** | 🟡 可选 | 不填就标"未指定领域"，但仍要写 |
| **reader_hint** | 🟡 可选 | 默认"知识工作者，读过研究生" |
| **length_hint** | 🟡 可选 | 默认 700 字 |

如果用户给的 concept 太常识（比如"什么是市场"），礼貌劝退："这个概念研究生以下就懂，我换一个更有嚼头的"——并主动抛一个相关的高阶概念。

## 输出三件套（强模板）

```markdown
# [抽象隐喻标题，3-6 个字]

[故事正文，600-900 字。现代场景：办公室 / 创业公司 / 城市 / 算法 / 产品]

[揭晓段：1-2 句话，简短有力，把概念名和故事钉死]

---

## 📘 概念解释

[2-3 段：定义 + 学术语境 + 一句话出处/提出者]

## 🔍 隐喻对照表

| 故事元素 | 对应概念要素 |
|---|---|
| [角色 / 事件 / 物件 / 台词] | [具体对应，不是"对应整体"] |

## ⚠️ 边界说明（一句话内）

[指出这个隐喻哪里不严密 / 哪里覆盖不到概念]
```

## 死守 6 条规则（违反就重写）

| # | 规则 | 怎么验 |
|---|---|---|
| 1 | 揭晓段之前的正文，**禁用概念原名**（含英文、缩写、变体、谐音、近义词） | grep 校验，命中则重写 |
| 2 | 揭晓段之前**禁止元叙述**（"这个故事在讲……"、"读者会发现……"） | 整篇 grep 校验 |
| 3 | **故事自身逻辑完整**——剥掉隐喻层，纯当小说也读得通 | 人读一遍自检 |
| 4 | 隐喻对照表 **一一对应**，每行有具体对应物 | 表格不允许出现"对应整体"、"象征全貌"这种空话 |
| 5 | **边界说明强制写**，哪怕只一句 | 模板有这一段，没填就不算完成 |
| 6 | **隐喻必须原生**——隐喻场景与概念必须**共享同一物理结构**，不是"找形象去套概念" | 见下文「原生隐喻检查法」 |

## 原生隐喻检查法（rule #6 的具体做法）

**核心原则**：好的隐喻不是"找一个形象去套概念"，而是**找到一个和概念共享同一物理结构的场景**。

判断方法——把隐喻场景的"灾难机制"列出来，看它和概念的"病态机制"是否一一对应：

| 隐喻场景的灾难 | 概念的病态 | 是否对应 |
|---|---|---|
| 门槛被雕得极其贴合旧人 | 模型拟合了训练集的每个样本 | ✅ |
| 新人/新场景被绊住 | 测试集表现崩塌 | ✅ |
| 越贴合旧人 → 越无法通用 | 拟合越强 → 泛化越差 | ✅ |
| 门槛失去"门槛"的功能 | 模型失去"模型"的功能 | ✅ |

如果**灾难机制一致**，就是好隐喻；如果只是"长得像"但物理结构对不上（比如"挨一拳"对应"反脆弱"——物理上挨一拳不必然变强），就是外贴比喻，要换。

### 优秀隐喻 vs 外贴隐喻

| 类型 | 例子 | 问题 |
|---|---|---|
| **优秀**（原生） | 门槛雕花 ↔ 过拟合 | 雕得越像 → 越不像门槛；拟合越强 → 越不像模型。物理同构。 |
| **外贴**（比喻） | 挨一拳 ↔ 反脆弱 | 挨一拳不必然变强；只是概念的形象化翻译。 |

**默认要写"优秀"级隐喻**；写不出来就先退到"外贴"，但要在边界说明里诚实标注。

## 揭晓段的写法（最容易翻车的地方）

揭晓段要满足 3 点：
1. **短**——1-2 句，不超过 60 字
2. **准**——把概念名钉死，不留模糊
3. **有余味**——用一句意象回扣故事，不要"这就是 XX 概念"

正例："这位产品经理发现自己走进了**反脆弱**。"

反例（违反规则 2）："原来这位产品经理经历的就是反脆弱——一种从波动中获益的能力。"

## 现代隐喻素材库（避免写空）

为了让故事不空洞，skill 内部维护一份隐喻素材清单，每次从里面抽：

- **公司场景**：产品经理、运营、HR、风控、销售、工程师、客服、老板
- **物件**：会议室、A/B 测试报告、OKR、周会、复盘文档、Slack 群
- **事件**：版本上线、数据暴跌、跨部门撕逼、汇报、融资、裁员
- **算法/数据**：训练集、噪声、过拟合、特征、退化、损失函数
- **城市/通勤**：地铁、红绿灯、出租车、外卖、暴雨、堵车

不要写魔法、修仙、动物拟人、古风——这些风格和目标读者（知识工作者）不匹配。

## 完成后自检三问

1. grep 揭晓段之前：概念名（含英文缩写、变体）有没有出现？**有 → 重写**
2. 故事里有没有"这个故事告诉读者"、"原来这就是"、"不难看出"这类元叙述？**有 → 重写**
3. 隐喻对照表每一行有没有具体对应物？**模糊 → 补具体**

任何一条没过，重写或局部修改，直到三问都过为止。
